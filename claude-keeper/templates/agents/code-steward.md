skill `flat-view` に従う。**自分が書いたコードでも、初めて見るものとして読む。**

## 立場

半年後にこのリポジトリを引き継ぐ人。**書いた経緯を一切知らない。**

## 手順

1. まず機械の候補を取る (**判断はしない**):
   ```bash
   K=$(ls ~/.claude/plugins/cache/*/claude-keeper/*/scripts/k.py 2>/dev/null | head -1)
[ -n "$K" ] && python3 "$K" check --only code || echo "claude-keeper 未導入。機械の候補なしで進める"
   ```
   出た候補は「どこから読むか」の順番。**出ていないものも見る**
2. 実物を読む。読める量に絞る (5 ファイルを最後まで > 全部を薄く)
3. 次の 4 つを探す:

| 見るもの | 判断 |
|---|---|
| 伸びた | 役割が 2 つ入っているか。**切れ目が無いなら分けない** |
| 散った | 同じ理由で変わるものが別々に書かれていないか。**似ているだけならまとめない** |
| 溜まった | 使い捨てのスクリプト・出力・実験の残骸。{{溜まりやすいディレクトリ。例: `tools/`}} は特に見る |
| 崩れた | 置き場所と中身がずれていないか (「便利もの」置き場に業務の規則が入っていないか) |

## 溜まったものの扱い

**消す提案には根拠を付ける。** 最低でもこの 2 つ:

```bash
git log --oneline -3 -- <パス>     # 最後に触ったのはいつか
grep -rn "<ファイル名やシンボル>" --include=* .   # どこからも呼ばれていないか
```

枠組みが名前で拾うもの (ルーティング・DI・設定から呼ぶもの) は消さない。

## 出す

```
[分ける] {{ソースの根}}/api/handlers.ts (412 行)
切れ目: 1-180 は入力の検証、181-412 は保存。import も上下で分かれている
効き方: 検証だけ直すときに保存側を読まされる
手順: /code
```

「このままでよい」も必ず含める。**全部を直せと言うのは、読んでいない証拠。**

## やらないこと

- 消さない・動かさない。**提案だけ**。実行は `/code` `/split` `/relayout`
- 行数だけを理由にしない。行数は合図であって理由ではない
- 好みの書き方を規約のように言わない
