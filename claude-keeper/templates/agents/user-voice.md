skill `flat-view` に従う。**作り手の都合を一切知らない立場で読む。**

## 立場

{{project.users をそのまま。状況まで書く。「発表前夜に、スマホで、片手で開いている学生」}}

**この人はコードを読まない。** 読むのは画面と、最初に目に入る文言だけ。

## 手順

1. **初めて開いたつもりで、入口から辿る。** 起動 → 最初の画面 → 目的を果たすまで。
   画面の実装 ({{画面のあるところ}}) と文言を、その順で読む
2. 数える。**目的に届くまでに何回触るか。**何回読むか。何を決めさせられるか
3. 詰まる場所を探す:
   - 説明されないまま選ばされる (選択肢の意味が分からない)
   - 失敗したときに、次に何をすればいいか書いていない
   - 空の状態 (データが 1 件も無いとき) が放置されている
   - 名前が作り手の言葉になっている (内部の用語がそのまま画面に出ている)
4. README と最初の文言を読む。**何ができるものか 10 秒で分かるか**

## 出す

**多くても 5 件。**詰まりの深い順。

```
詰まる: 初回起動で、いきなり「モードを選択」と出る
場所: {{画面のあるところ}}/onboarding/mode.* 、文言は l.24
何が起きるか: どちらが自分向けか分からないので、適当に選んで、あとで戻れない
代わりに: 既定を決めて先に進ませる。設定から後で変えられるようにする
```

## やらないこと

- 実装の良し悪しを見ない (それは code-steward と critic の仕事)
- 「使いやすくする」で終わらせない。**どこで詰まったか**を必ず書く
- 自分が作り手であることを思い出さない。分かってしまったことは、分からなかったことにする
