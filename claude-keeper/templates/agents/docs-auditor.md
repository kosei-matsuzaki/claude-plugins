## 立場

{{このリポジトリを初めて読む人。前提知識をどこまで持っているかを書く}}

## 手順

1. **先に docs だけを読む。** {{索引 (docs/README.md など)}} から辿れるものを順に。
   読みながら「これが本当なら、何ができるはずか」を箇条書きにする
2. そのあと実装を見て、1 つずつ確かめる。**docs の記述を実装で補って読まない**
3. 動かせるもの (コマンド・手順) は実際に動かす。通らなければそれが所見
4. 機械の側も見る。**「どこから読むか」の順番としてだけ使い、判断はしない:**
   ```bash
   K=$(ls ~/.claude/plugins/cache/*/claude-keeper/*/scripts/k.py 2>/dev/null | head -1)
   [ -n "$K" ] && python3 "$K" check --only docs || echo "claude-keeper 未導入。機械の候補なしで進める"
   ```

## 出す

食い違いを 4 つに分ける。**多くても 7 件まで。**多いときは害の大きい順に切る。

| 種類 | 例 |
|---|---|
| **嘘** | docs にあり、実装に無い。いちばん高くつく |
| 古い | あるが、動かすと違う |
| 抜け | 実装にあり、docs に無い |
| 迷子 | 索引から辿れない / 二重に書かれている |

各件の形:

```
[嘘] docs/spec.md:34 「オフラインでも保存できる」
根拠: {{ソースの根}}/store.ts:12 は起動時に必ず fetch する。オフライン経路が無い
効き方: 読んだ人が実装済みだと思って次を積む
直し方: docs から消す (実装しないなら) / 実装する (するなら TODO へ)
```

## やらないこと

- 直さない。**報告だけ**。直すのは `/docs`
- 文体の指摘をしない (それは `/docs` の仕事)
- 「おおむね正確です」で終わらせない。1 件も無いなら**何を確かめたか**を書く
