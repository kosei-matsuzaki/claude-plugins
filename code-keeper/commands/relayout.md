構成を規約に戻す。**中身の書き換えはしない。動かすのと、向きを直すのだけ。**

## 1. 現状を出す

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ck.py" check --only layers
```

出るのは 3 種類:

| 種類 | 意味 |
|---|---|
| 層の逸脱 | 依存の向きが規約と違う。**いちばん重い** |
| どの層にも属していない | 置き場所を決めずに作られた |
| 膨らんだディレクトリ | 分け方を決めていない |

## 2. 逸脱を 1 本ずつ見る

**移す前に、逸脱が本物か決める。** 逸脱には 3 通りある:

| 実態 | すること |
|---|---|
| 近道の import(内側から外側を直接呼んだ) | **向きを直す**。3 節へ |
| ファイルの置き場所が違うだけ | **移す**。4 節へ |
| 規約のほうが実態に合っていない | **規約を直す**。`allow` か `path` を変える |

3 つ目を怖がらない。**規約は現実に合わせて直すもの。**
ただし「面倒だから allow を広げる」のは崩れの始まり。理由を書いて直す。

## 3. 向きを直す

内側が外側を呼んでいるとき、直し方は 2 つ:

1. **呼ぶ側を外へ出す** — その処理が本当は外側の仕事だったとき(たいていこれ)
2. **境目を挟む** — 内側に interface / 抽象を置き、外側がそれを実装して渡す

**2 は先にやらない。** 1 で済むなら 1。抽象は、2 つ目の実装が来てから作る。

## 4. 移す

- **先に一覧を出して承認を取る。** 「どれを、どこへ、なぜ」を表で見せる
- `git mv` で動かす(履歴を残すため)
- **import を全部直す。** grep で、旧いパスが 1 つも残っていないことを確かめる
- 相対 import が深くなりすぎたら(`../../../`)、置き場所を考え直す合図

## 5. 膨らんだディレクトリ

ファイル数が上限を超えたところは、**まず分ける軸を決める**。
役割で分けるか、機能で分けるか(skill `code-policy` の「層をどう切るか」)。
**軸を決めずに数だけで分けない** — 数で割ると、次に足すときにまた迷う。

## 6. 確かめる

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ck.py" check --only layers
```

- **ビルドが通ること。** import を直し切れているかはこれでしか分からない
- テストがあれば回す
- 逸脱の件数が減っていること。**増えていたら戻す**

## 7. 報告

- 直した逸脱と、その直し方(向きを直した / 移した / 規約を直した)
- **規約を直したものは、理由を必ず書く**
- 残した逸脱と、残した理由
