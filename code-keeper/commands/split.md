---
description: 長くなったファイルと関数を分ける。行数ではなく役割で切る
allowed-tools: Bash, Read, Write, Edit, Glob, Grep
argument-hint: "[ファイル名]"
---

伸びたファイル・関数を読める大きさに戻す。**動きを変えない。**

## 1. 対象を決める

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ck.py" check --only size
```

`$ARGUMENTS` にファイル名があればそれだけ。無ければ**上限を超えたもの**が対象。
超過がゼロなら、いちばん長いものを対象にするか聞いて終わる。

**一度に 1 ファイル。** まとめて分けると、壊れたときにどれが原因か分からなくなる。

## 2. 切る場所を決める

**行数は理由ではなく合図。** 対象を読んで、切れ目があるかを見る:

| 見るもの | 切ってよい印 |
|---|---|
| import | 上半分と下半分で使っているものが違う |
| 状態 | 一部の関数だけが触っているフィールドの塊がある |
| 変更の理由 | 「この部分だけ別の理由で変わる」と言える |
| 関数の説明 | 「〜して、〜する」と `and` が入る |

**切れ目が無いなら分けない。** 長いだけで一枚岩の関数はある。
そのときは「分けない」と報告して、理由を書いて終わる。**それも正しい結果。**

## 3. 切る

関数を分けるとき:

1. 抜き出す塊を決め、**入る値と出る値だけ**を見る。塊の外を触っていたらまだ切れない
2. 新しい関数に名前を付ける。**名前が付かないなら、切り方が間違っている**
3. 元の位置から呼ぶ。**この時点で動きは変わっていないこと**

ファイルを分けるとき:

1. 新しいファイルの置き場所は**規約の層に従う**(`.code-policy.yml` の `layers`)
2. `git mv` か、新規作成 + 元から削除。**import を全部直す**
3. 分けた先が 1 つの役割になっているか。ならないなら切り方を変える

## 4. 確かめる

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ck.py" check --only size,layers
```

- **テストがあれば回す。** 無ければ、呼び出し元を grep して数が合うか見る
- 型検査・lint があれば回す
- 層の逸脱が**増えていない**こと(分けた先が別の層に落ちていないか)

## 5. 報告

- 「420 行 → 180 行 + 新規 2 ファイル」の形で
- **切らなかったものと、その理由**(ここがいちばん大事)
- 動きを変えた箇所があれば必ず言う。**無いなら「無い」と言い切る**
