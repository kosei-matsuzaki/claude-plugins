コードの現状を報告する。**ファイルは一切書き換えない。**

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ck.py" check $ARGUMENTS
```

| 引数 | 効果 |
|---|---|
| `--since <ref>` | その参照から変わったファイルだけを見る。リリース前や PR の点検に |
| `--only <区分>` | `size` `layers` `dupes` `dead` `comments` から選ぶ |
| `--strict` | 指摘があれば終了コード 1。CI で使う |
| `--show-judged` | 「このままでよい」と判断済みで黙らせているものの中身を出す |

出力をそのまま貼らず、次の形にまとめて報告する:

1. **いま直すべきもの** — 層の逸脱、コメントアウトされたコード、長すぎる関数
2. **溜まってきたもの** — 重複、使われていないファイル、膨らんだディレクトリ
3. **どのコマンドで解けるか** — `split` / `unify` / `relayout` / `comment` / `prune`

件数がゼロの区分は「なし」の一行で済ませる。**問題が無いなら短く終わる。**

## 数字を鵜呑みにしない

このプラグインは構文解析をしない。次は**誤検出**として、報告するときに省く:

- 生成されたコード → `scope.exclude` に足すことを勧める
- 動的に呼ぶもの(DI・反射・文字列でのルーティング)が「使われていない」に出る
  → `dead.entrypoints` に足すことを勧める
- 意図的な写し(実験の条件違い、移行中の新旧) → `duplication.ignore` を勧める

**同じ誤検出が 2 回出たら、コードではなく規約を直す。**
規約ファイルが無い場合は `/code-keeper:init` を勧める。

## 数えられないものは出ない

`check` が出すのは数えられるものだけ。**名前の不一致・抽象の高さの不揃い・
コメントの中身・形も名前も違うが同じことをしている処理**は 1 件も出ない。
「0 件だから健全」とは報告しない。**中身を見るなら `/code-keeper:review`** と添える。
