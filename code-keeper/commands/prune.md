---
description: 使われていないファイルとコードを消す。消す前に必ず確かめる
allowed-tools: Bash, Read, Write, Edit, Glob, Grep
argument-hint: "[--dry-run]"
---

残骸を片づける。**このコマンドだけは、間違えると動くコードを消す。**
出るのは全部**候補**で、確かめる手順を飛ばしてはいけない。

## 1. 候補を出す

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ck.py" check --only dead
```

2 種類出る:

| 種類 | 確からしさ |
|---|---|
| どこからも import されていないファイル | 比較的高い。ただし枠組みが名前で拾うものは外れる |
| 定義だけで呼ばれていない名前 | **低い**。動的に呼ぶものを見抜けない |

## 2. 1 つずつ確かめる

**機械の出力だけで消さない。** 候補ごとに、消してよい根拠を自分で取る:

```bash
git -C . log --oneline -3 -- <path>      # いつから触られていないか
grep -rn "<ファイル名の語幹>" --include="*" .   # 文字列で参照されていないか
grep -rn "<関数名>" .                     # 別名 import・再エクスポート経由で使われていないか
```

**消してはいけないもの:**

| 種類 | 見分け方 |
|---|---|
| 枠組みが名前で拾う | `pages/` `routes/` `migrations/` `conftest.py` `main.*` |
| 文字列で呼ばれる | DI の登録名・ルーティング表・設定ファイルに名前がある |
| 外へ公開している | ライブラリの公開 API、`index.ts` の再エクスポート |
| テストからだけ使う | テストを `scope.exclude` に入れていると参照が見えない |
| 消したばかりのものの片割れ | 今のセッションで作った・移した途中 |

上のどれかに当たったら、**消さずに規約の `dead.entrypoints` / `ignore` に足す。**
同じものが毎回出るのを止めるほうが、消すより価値がある。

## 3. 承認を取る

**消す前に一覧を見せる。** 「ファイル / 最終更新 / 消してよいと判断した根拠」の表で。
`$ARGUMENTS` に `--dry-run` があれば、**ここで終わる**(消さない)。

## 4. 消す

- `git rm` で消す(履歴に残す)
- **1 コミットに 1 種類。** ファイルの削除と関数の削除を混ぜない
- 消したあと、そのファイルを import していた行が残っていないか grep する

## 5. 確かめる

- **ビルドが通ること。** 通らなければ即座に `git checkout` で戻す
- テストを回す
- **動的に呼ぶ箇所は、テストでも通らないことがある。** 消したものが
  設定ファイル・環境変数・文字列で参照されていないか、もう一度 grep する

## 6. 報告

- 消したもの(ファイル数 / 行数)
- **消さなかった候補と、その理由**
- 規約の `dead.entrypoints` / `ignore` に足したもの

戻し方も書く: `git revert <sha>`。**消したものは戻せると必ず伝える。**
