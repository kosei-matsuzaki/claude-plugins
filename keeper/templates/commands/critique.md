**機能が要るか、順番は合っているか、その解き方かを疑う。**コードが正しいかは見ない。

## 1. 立場を切り離す

**このコマンドの本体は agent に投げる部分。**同じ会話で実装を決めた Claude は、
その判断に肩入れする。`.claude/agents/critic.md`({{user-voice がいるなら「と user-voice.md」}})へ、
**会話の経緯を渡さずに**投げる。

| 引数 | 誰が読むか |
|---|---|
| なし | {{既定で走らせる役}} |
| `--as <役名>` | その立場だけ |
| 論点 / パス | その範囲だけを見せる |

## 2. 何を渡さないか

渡すのは範囲だけ。**渡してはいけないもの:**

- なぜその設計にしたか(会話でしか存在しない理由)
- どれだけ時間をかけたか
- 何を急いでいるか

これらは「直さないほうがよい理由」として効いてしまう。判断材料ではない。

## 3. 台帳を先に読む

```bash
cat .claude/judgments.yml 2>/dev/null
```

**前に「いまは直さない」と決めたことを蒸し返さない。**覆すなら、
「何が変わったから覆すのか」を言う。言えないなら黙る。

## 4. このプロジェクトで特に疑うところ

{{判断が割れやすい・後戻りしにくい論点を 2〜4 行。「一度外して戻した機能」「選ばせているものの数」など}}

## 5. 出す

**多くても 5 件。**効き方の大きい順。各件はこの形:

```
所見: <一文>
根拠: <path:line か コミット。無ければ「印象」と明記>
効き方: <直すと何が変わるか。誰にとって変わるか>
代わりに: <別の解き方。無いなら「無い」と書く>
確からしさ: 確か (読んだ) / 推測 (測っていない)
```

最後に **1 行だけ**、いちばん効くものを名指しする。

意見が割れたら、**割れたまま出す。**そこが本当の論点。

## 6. 決まったら残す

「いまは直さない」と決めたものは `.claude/judgments.yml` へ
(書式は `/standup` の 4 節)。

## やらないこと

- 褒めない。良い点は最後に 1 行だけ
- コードを書かない。**このコマンドは何も直さない**
- 「一般にこうすべき」で言わない。**このリポジトリの証拠で言う**
