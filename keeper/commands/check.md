**書き込みを一切しない。**いま何が置かれていて、どこがずれているかだけを出す。

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/k.py" check $ARGUMENTS
```

| 引数 | 何が変わるか |
|---|---|
| なし | 3 領域とも |
| `--only docs` / `code` / `crew` | その領域だけ(カンマで複数) |
| `--since <ref>` | その参照からの差分に絞る |
| `--strict` | 指摘が 1 件でもあれば終了コード 1(CI 用) |
| `--show-judged` | 台帳で黙らせているものの中身も出す |

**CI に入れるなら `--since` から始める。**既存のコード全部に当てると、
最初の 1 回で真っ赤になって誰も見なくなる。

## 出力を読んだあと

機械が出すのは候補で、判断ではない。**そのまま直しに行かない。**

| 出たもの | 次にすること |
|---|---|
| 長すぎる / 重なっている / 使われていない | `/code`(**読んでから**決める) |
| 長すぎる文書 / 索引漏れ / 規約外の置き場所 / 文書が動いていない | `/docs` |
| 参照切れ・雛形の埋め残し | `/keeper:refresh` |
| 自立していないところ | `/keeper:refresh` |
| 生成物への手直し | 中身を読む。**手で直した内容のほうが正しいことが多い** |
| 統合前の規約 / 台帳が残っている | `/keeper:init` が 1 つにまとめる |

## 外れていたら黙らせる

機械が数えられないことにも口を出すので、外れも出る。**外れは黙らせる。ただし理由を書く。**

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/k.py" judge \
  --key "ref:scratch/" --path CLAUDE.md \
  --decision "直さない" --why "実行時に作られる一時領域。リポジトリに無いのが正しい" \
  --until 2026-12-01 --by "/keeper:check"
```

`--until` を書くと、その日を過ぎたときにもう一度言う。**運営の判断はたいてい
期限付き**なので、「永久に黙れ」と書く前に期限を考える。

## 機械には見えないもの

`check` に出ないものがある。**出ないことを健全と読まない。**

- 形も名前も違うが同じことをしている処理 / 同じものを指す別々の名前
- 1 つの関数に混ざった、高さの違う操作
- そのコメントが「なぜ」か、言い換えか
- **CLAUDE.md や docs に書いてあることが正しいか**(実在するかしか見ていない)
- `stance` が立場になっているか / 置いた役が実際に呼ばれているか
- **この規模・この性格に、その構造が合っているか**

これらを見るのは、生成された `/standup` `/code` `/docs` `/critique`。
